# Research: Book Content Structure and Learning Path

This document outlines the research for organizing book content and implementing a weekly learning path in Docusaurus.

## Docusaurus Content Organization

Docusaurus primarily uses a file-system based approach for organizing documentation.

-   **Docs Plugin**: The `@docusaurus/plugin-content-docs` plugin is used to manage documentation. It allows defining a `path` (where the markdown/MDX files are located) and a `routeBasePath` (the URL prefix).
-   **Sidebars**: Navigation is typically handled via `sidebars.js`. This file exports an array of sidebar items, which can be categories, links, or autogenerated items based on directory structure.
    -   **Categories**: Can be used to group related documents, serving as "modules".
    -   **Autogenerated Sidebars**: Docusaurus can automatically generate sidebar items based on the file system structure within a docs folder. This is useful for `docs/module1/chapter1.mdx`.
    -   **Front Matter**: MDX files can include front matter (YAML at the top) to define titles, slugs, and other metadata. This can be extended to include information like `week: 1` for learning path association.

## Implementing Weekly Learning Path

There are several approaches to implement a weekly learning path:

1.  **Custom Sidebar Category**: Create a top-level category in `sidebars.js` like "Weekly Learning Path", and then define sub-categories for each week, manually linking chapters to them. This might involve duplicating chapter entries or linking directly.
2.  **Custom Plugin**: Develop a custom Docusaurus plugin that reads metadata (e.g., `week: X` from MDX front matter) and generates a learning path structure, either as a new page or injected into the sidebar.
3.  **Custom React Component**: Create a React component that reads metadata from all MDX files (possibly pre-processed) and dynamically renders the learning path on a dedicated page or within the sidebar. This would likely involve using Docusaurus's client-side APIs for accessing docs metadata.

**Decision**: Initially, we will explore using Docusaurus's existing sidebar customization capabilities combined with MDX front matter to define the weekly learning path. If that proves too rigid, a custom React component or plugin will be considered.
