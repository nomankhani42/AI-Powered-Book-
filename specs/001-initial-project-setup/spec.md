## User Scenarios & Testing *(mandatory)*

### User Story 1 - Read the Interactive Book (Priority: P1)

A user can navigate the interactive book website, read the content, and view the embedded media.

**Why this priority**: This is the core functionality of the project.

**Independent Test**: The Docusaurus site can be built and served locally, and the content is visible and correctly formatted.

**Acceptance Scenarios**:

1. **Given** the project is set up, **When** the user navigates to the website, **Then** the book's home page is displayed.
2. **Given** the user is on the website, **When** they click on a chapter in the navigation, **Then** the content of that chapter is displayed.

### User Story 2 - Interact with the RAG Chatbot (Priority: P2)

A user can ask the chatbot questions about the book's content.

**Why this priority**: This is a key feature that differentiates this project.

**Independent Test**: The chatbot UI is visible, and it can respond to a hardcoded query.

**Acceptance Scenarios**:

1. **Given** the user is on any page of the book, **When** they type a question into the chatbot, **Then** the chatbot displays a response.
2. **Given** the user highlights a section of text, **When** they right-click and select "Ask about this selection", **Then** the chatbot UI appears with the selected text as context.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST be a Docusaurus 3.x website.
- **FR-002**: System MUST use Spec-Kit Plus.
- **FR-003**: All book content MUST be in MDX format under `/docs/`.
- **FR-004**: The website MUST have an embedded React chatbot.
- **FR-005**: The chatbot MUST be ableto answer questions based on the entire book.
- **FR-006**: The chatbot MUST be able to answer questions based on user-selected text.
- **FR-007**: The backend MUST be a FastAPI application.
- **FR-008**: The backend MUST use either OpenAI Agents SDK or LiteLLM with Gemini 2.0 Flash.
- **FR-009**: The ingestion pipeline MUST use Qdrant and Neon Serverless Postgres.
- **FR-010**: The project MUST have a GitHub Actions workflow for CI/CD to GitHub Pages.
- **FR-011**: The project MUST include deployment instructions for the backend on Railway, Fly.io, or Render.

### Key Entities *(include if feature involves data)*

- **Book**: The collection of all course content in MDX format.
- **Chapter**: A single MDX file representing a chapter of the book.
- **Chatbot**: A React component that facilitates user interaction with the RAG backend.
- **Query**: A question asked by the user.
- **Response**: An answer generated by the RAG backend.
